# 来源格式与业务语义

记录遵循 MARC21 ISO2709。

## 字节边界

* 24 字节 leader；目录项为 tag 3、字段长度 4、起点 5 个 ASCII 字节；目录与字段
  以 0x1e 结束，记录以 0x1d 结束。
* leader/00-04 声明整条记录长度，leader/12-16 声明字段起点 base。目录项声明的
  字段长度包含字段终止符，起点相对 base 而非文件。
* leader/20-23 的目录项长度图决定目录项长度（默认 12 = 3+4+5）。
* leader/10 是指标位数（默认 2），leader/11 是子字段标识符长度（默认 2，含 0x1f）。
* 所有定位只使用这些声明值；解码后的字符数与目录长度无关。中文标题的 UTF-8
  字节数是字符数的三倍左右，按字符数切分会把后续字段整体错位。

## 边界可信度

外层边界由 leader 声明长度与其末字节 0x1d 共同确认：

* 剩余字节不足 24 或不足声明长度、声明长度过小、声明末字节不是 0x1d：抛出
  `BoundaryError`，批量停止，`stopped` 给出声明长度、实际字节、期望结束符位置
  与原始尾部十六进制。调用方不得向后扫描 0x1d 猜测记录起点。
* 边界可信后，目录项非数字、字段越过记录、字段终止符缺失、目录未连续覆盖字段区、
  子字段代码截断、UTF-8 损坏等属于记录内部错误：该记录标记 `invalid` 或
  `unsupported_encoding`，下一记录仍从“当前偏移 + 声明长度”开始。

## 字符集

这里只承诺 UTF-8（leader/09 = `a`）。其它值（空格代表 MARC-8、`b`、`c` 等）
整条记录隔离为 `unsupported_encoding`，不解码、不猜测、不用 latin1 兜底。
UTF-8 解码失败时记录 `invalid_utf8` 与坏字节位置，文本值为 null，原始切片仍在，
绝不产生 U+FFFD。

## 字段表示

控制字段（tag 以 00 开头）没有指标位，整个字段体是文本。其余字段先取 leader 声明
的指标位，再按 0x1f 拆子字段；重复 700、重复 650 和重复子字段（如两个 `e`）
保持目录顺序与子字段 ordinal。导出书名（245 `a`/`b`）、责任者（100/110/111/
700/710/711 的 `a` 与 `e`）、出版信息（260/264 的 `a`/`b`/`c`）时保留字段序号、
字段起止偏移和每个子字段的原始切片。

## 书目身份

001 是馆内控制号，必须与 003 机构代码及来源一起解释。身份键为
`(来源, 003, 001)`；不同馆的相同 001 是两条独立书目，不会互相覆盖。003 缺失时
退化为 `(来源, 001)` 并在 `identity.basis` 标为 `001+source`；001 缺失则无法关联，
记为 `unassigned`。

## 收件与修订

交付批次身份是 `(来源, sha256(整批原始字节))`，重复导入同一批字节返回同一收件
记录，不会产生新修订。记录修订身份是记录自身摘要：同一书目身份下新摘要为
`revision`，已有摘要为 `resend`（原件重送）。整批外层边界不可信时整批拒绝写入，
不留下部分收件；单条内部损坏时交付仍可建立，但该条只保留证据、不写修订。

## 演练数据

本地演练夹具由 `sampledata.py` 生成，均为虚构业务数据：`sample` 正常批量、
`revision` 同 001 新内容、`resend` 原件重送、`repeated` 中文与重复字段、
`agencies` 跨馆同 001、`mixed` 中间单条损坏可继续、`truncated-tail` 尾部截断、
`invalid` 首条截断、`latin1` 非 UTF-8 隔离。生成不会下载资源。

本地 HTTP 演练器采用方法与原始路径作为路由键，值为按调用次数返回的响应数组，
耗尽后维持最后一项。响应可定义 status、headers、text/base64、require_headers、
chunk_bytes、disconnect_after。每次请求保留方法、路径、头与正文摘要表示；演练器
只监听回环地址。

原始输入上限 16 MiB 是现有查看入口的保护值，不代表持续采集需一次读完整来源。
格式含义和截断错误不能被 HTTP 200 覆盖。
